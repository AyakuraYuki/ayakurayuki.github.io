## 阶段一的导入范围

只复制 MiSans Regular、Bold 字体以及字体自带的许可证与 NOTICE。没有复制三维模型、GLB、Blender 工程、场景入口或 Service Worker。没有重新制作美术。

`rhine-upstream.lock.json` 为以后导入保存 118 个上游文件的路径、大小与 SHA-256，其中包含模型及生成源文件；清单不是已经完成运行时集成的声明，也不是这些资产的再授权。

```sh
cd site
npm run check:upstream
# 可选的开发期只读核对；日常构建不依赖这个目录
npm run check:upstream -- /absolute/path/to/RhineLabUI
```

本阶段已增加完整源码/模型/源脚本快照以及独立派生适配，已导入清单以 lockfile 为准；上段四个字体文件是第一阶段的历史导入范围。

当上游继续前进时，第二条命令应失败并提示审核升级，不能偷偷刷新记录。日常 `npm run verify` 不读取上游工作目录。

## 阶段二接入边界（已接入）

博客自有的 `Post` / 列映射 / 预览数据不直接修改上游固定 40 档案数据。计划将场景封装为明确的初始化、选档、进入/离开预览、销毁接口；博客路由管理留在博客侧。

- 内容输入：稳定文章 ID、五个展示分区、各区不等长 ID 列表、简短标签。
- 事件输出：选中、请求预览、请求阅读、关闭预览。
- 生命周期：挂载/销毁时清理 RAF、监听器、声音和 GPU 资源；正文外链直达无需创建场景。
- 原片回放仍使用原来的内容位置规则；博客分类循环单独适配。
- HTML 阅读区域不借用场景的键盘/触摸事件；状态按稳定 ID 保存，而不是数组下标。
- 初次不启用上游 PWA。不能直接导入上游的根作用域 Service Worker、正式域名和完整资源缓存策略。

当前实现与差异记录见 `STAGE-2.md` 和 `rhine-adapter.patch`。没有把整个上游重构成组件库，也没有把博客业务合并进上游演示；博客侧入口与场景适配独立保存。

## 接收上游更新

1. 单独创建上游升级变更，记录 old/new commit；不与文章更新混合。
2. 对比已导入文件、相关资源、生成脚本与上游规范。
3. 导入代码与匹配 GLB，重放清晰可审查的博客适配补丁。
4. 跑旧文章检查和三维专项回归，视觉确认后更新锁定版本。
5. 失败则保留旧版本；博客内容继续发布，不要求实时跟随上游 main。

以后是否抽取共享库，取决于至少一次真实集成/升级形成的稳定边界。当前不新增第三个仓库、不使用漂移的 Git 依赖或主题子模块。

## 部署审计

2026-09-09 通过 GitHub 公共仓库 API 只读确认默认分支为 `hugo` 且 Pages 已启用。旧仓库工作流自动触发仍为 `master`，另有手动入口。尚未读取账户级 Pages 来源、环境保护规则或最近一次生产部署运行，因此**不推断哪条链路实际更新线上站点，也没有修正该差异**。

这项审计是生产切换的前置条件，不阻止本地内容适配。迁移工作流只保存 artifact，不占用现有生产 Pages。
