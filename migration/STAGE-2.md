# 第二阶段：三维文章入口与预览

## 范围与版本

上游继续固定在 `e3137770bac38044988e3a67973397b7c1e31b96`；没有修改原 RhineLabUI 工作目录、灯光、材质、抽取高度、原模型或生成脚本，没有重新制作美术。源快照保存在 `site/vendor/rhine/`，实际 GLB/音频/字体部署在 `site/static/`。

- `/`：三维文章档案；第一次进入可看开场，也可跳过。遵循系统减少动画设置。重播在设置中。
- `/posts/`：第一阶段已验收的普通文章索引，保持无需三维或 JS 即可阅读的路径。
- `/p/<slug>/`：原文章 URL，不变。直接进入时不加载 Three.js、GLB、音频或开场。
- `/?post=<slug>`：定位指定文章预览的辅助入口；分享文章仍使用 `/p/<slug>/`。
- 独立模型查看器继续使用原拆解资产、清晰/磨砂与复位规则。

正文往返暂时使用正常文档导航，而不是未经验证的跨页 SPA 生命周期。原文章及其 25 个附件仍保持字节不变。

## 真实文章与物理位置分离

`site/src/archive/catalog.ts` 是纯数据适配器，输入已发布 Post 元数据与标题目录。标题、摘要、标签、URL 来自同一份 Markdown，不维护第二份正文 JSON。SSR 时输出转义后的 JSON 数据块，不通过执行内联 JavaScript 注入文章。

- 五个分区保持技术笔记、项目档案、基础设施、生活记录、公告通知；当前数量为 29/6/1/1/1。
- 现有多个分类保留在文章元数据中；展示分区按五列配置顺序取首个匹配，新分类无匹配时进入技术笔记，不静默丢文章。
- `X-001` 是显示序号，不是收藏或会话身份。收藏和列选择记忆使用 `post:<bundle>` / 显式文章 ID。
- 29 篇的列用八个固定按钮组成局部窗口；少于八篇按真实数量显示，不制造八篇假文章。
- 一篇文章的列仍沿上下方向移动到相邻的同文副本，总数为 1。
- 空列有一张明确不可读的占位档案、计数 0、禁用预览；纯函数测试覆盖，当前实际语料无空列。
- 物理模型池始终为 9×32=288；不为每篇文章新增永久模型。

原数据中 `row=12+ordinal` 可能大于31，不能再拿 `lane*32+row` 同时作为文章身份。适配层把旧 slot 限制为原片锚点，把交互文章身份和无限逻辑 cell 单独保存。相机运动和原片 160 个位置不依赖博客文章数量。

## 连续循环与归位

保持上游的选中/归位运动，唯一的数据映射补充是：内容查询同时考虑 `coordinateOrigin`。原来的八行周期 rebase 可以继续保持波浪相位，但不能假设每列的文章周期也是八。新映射在30,000次混合正反向导航及 rebase 后继续定位同一文章。

归位副本仍按实际 cell 区分，快速切回保留当前升降/旋转状态。模型和卡片没有因为博客标题变长而向前或横向移动重新构图；只调整右侧 DOM 排版。

## 预览与状态

预览显示文章标题、发布日期、阅读时长、标签、摘要、目录和相关档案。目录链接直接进入正文对应章节。全文链接是真实 `<a>`，支持新标签打开，不依赖模拟点击导航。

`rhine-blog:archive-session:v1` 保存选中文章、五列选择记忆和预览/阵列模式。返回或刷新按稳定 ID 恢复；失效 ID 安全回退。精确滚动位置、转场和连续摄像机往返留待第三阶段。

收藏使用 `rhine-blog:saved:v1`，声音/画质偏好使用 `rhine-blog:settings:v1`，不读取或覆盖原复刻站偏好。博客初次默认静音，可在设置开启，开启后使用原原创配乐/音效资源。

页面离开时释放 RAF、全局事件、过渡、音频、模型与渲染器；进入浏览器往返缓存时暂停，恢复时继续。单独查看器也有清理入口。代码不安装全局路由或拦截正文页面的方向键。

## 源码边界与差异审核

- `site/vendor/rhine/` 是不可修改快照，哈希由上游 lockfile 校验。
- `site/src/archive/` 是博客侧适配。`main.ts`、`scene.ts`、`model-viewer.ts` 派生自上游，对比记录在 `migration/rhine-adapter.patch`。
- 其他原生运动、品牌曲线、材质、镜头适配、音色、查看器控制等从 vendor 直接引用。
- `npm run check:upstream` 同时检查原始文件与适配差异；若需更新适配，显式生成并审阅 patch，而不是让 build 自动改写它：

```sh
cd site
node --input-type=module -e 'import {adapterPatch} from "./scripts/adapter-patch.mjs"; import {writeFileSync} from "node:fs"; writeFileSync("../migration/rhine-adapter.patch",adapterPatch())'
```

下一次上游升级仍需单独比较并验证，不自动跟随 main。本阶段不是上游升级演练。

## 不变的发布边界与限制

- 未启用上游 PWA：不复制其 manifest、update 入口或 Service Worker 到发布目录。`vendor/src/pwa.ts` 只作为原始快照保存，从未进入运行入口。
- 预览仍有 noindex，CI 仍只有检查和 artifact，没有部署权限。
- 本次不处理旧 Pages 来源差异、不合并到 hugo/master、不修改 CNAME。
- 3D 入口有大型 JS chunk 和原字体/资产体积开销；没有为了消除警告自动降低手机画质。正文路由独立且不加载三维 bundle。
- 手机浏览器自动化只代表 Chromium 视口/触摸模拟，不宣称 iPhone Safari 实机通过。
- 全文搜索、RSS、归档/标签独立页面、完整阅读转场及实机性能仍属于后续阶段。
